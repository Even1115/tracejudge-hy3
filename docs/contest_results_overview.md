# TraceJudge-Hy3｜一页成果总览

**课题二 · 代码任务方向｜个人／活动作品，非腾讯官方发布｜更新：2026-09-10 工作副本**

给需要检查 AI 生成代码的开发者与评测人员：除了运行测试，还检查解题说明是否成立、代码是否实现了所述计划，并给出错误位置、类型和可核查证据。Hy3 负责结构化解答与过程判断，规则及执行证据提供补充检查；评估对象是可观察的解答文本与代码。

## 两个案例看懂价值

| 案例 | 公开材料中的问题 | 系统与证据能说明什么 |
| --- | --- | --- |
| **测试通过，过程承诺有缺陷：`tuple_str_int`**（MBPP 开发样本） | 声称 `"(5,)"` 返回 `(5,)`，但其分割、逐项 int 转换算法会遇到空片段 | 两方法均指出过程问题；历史官方 base/plus 聚合通过不变。边界分析是静态推演，未新增候选执行；标签已按预测后 AI 辅助复核修订。[复核依据](experiments/process-method-validation-v2-repair.md) |
| **计划正确，代码失配：`find_char_long`**（构造探针） | 计划保留长度 `>= 4` 的单词，代码却用 `> 4` | 最新两方法均检出 alignment 错误并引用代码 L2。代码引用支持失配解释，但冻结金标采用计划步骤 S2，不能自动算作步骤命中。[定位审核](experiments/process-location-format-v2.md) |

工作流：**需求条款 → Hy3 解答与步骤 → 静态／执行检查 → 过程判断、错误类型及位置 → 查看证据与导出报告**。有执行支持的适用错误证书可重放；静态推演不标成已执行反例。

## 结果与证据

各行是不同实验，不相加、不合成排行榜。近期过程信号采用 reasoning_correct AND plan_code_aligned，功能结论单列。

| 实验 | 已完成的结果 | 限制与出处 |
| --- | --- | --- |
| **36 条开发样本，两方法** | 修订标签 v2 下，两方法均准确 **33/36**、召回错误 **2/5**、误报 **0/31**；有效覆盖均 36/36 | 同一批预测离线重计分，原口径为 32/36。标签含预测后 AI 辅助复核，非独立盲审；仍漏检 3 条错误。[说明](experiments/process-method-validation-v2-repair.md) |
| **12 条试点，四证据条件，五轮重复** | D 条件对 `max_product` 仅 **2/5** 轮检出；`division_elements` **0/20** 检出 | 原标签与方案固定；单轮优势未稳定复现。失败和产物丢失事故单列披露。[重复报告](experiments/process-pilot-repetition-v1.md) |
| **3 条构造探针，新定位规范，两方法** | 各 **3/3** 检出、层级 **3/3**、步骤 **1/3**；精确位置 **0/3**；补充同源引用覆盖 **1/3** | 本轮两方法持平；全是错误样本，误报率无分母。补充指标为事后机械分析，不能替代精确匹配。[协议](experiments/process-location-format-v2.md) |
| **历史 57 条探索性研究，五方法** | Structured 检测 **56/57**；+AST 步骤定位 **10/11**；Full 检测 **55/57**、误报 **1/43** | 检测与定位最佳来自不同方法，不证明 Full 普遍更优；包含 15 条构造轨迹。[冻结结果](releases/phase4/phase4_contest_results_overview_v1.md) |

最新三探针定位规范真实运行使用 **基线 5 次请求、假设核对 3 次请求**，最终六个判断全部成功；本轮没有 code_span 格式失败。基线经历一次超时和一次判断矛盾修复，usage 不完整；费用未知。这是一次小样本观察，不是稳定降本结论。两方法的原始判断与规则合并计分一致，规则未改变判断。

**可核查来源：** 36 条使用 `dev36-label-rescore-20260910-v2/label-rescore.json`；最新探针使用 `probes3-location-comparison-20260910-v1/comparison.json` 和 `probes3-location-review-20260910-v2/location-review.json`，均位于本地 `artifacts/experiments/process-method-v2/`。探针预测 SHA-256：基线 `b501e131de1382dbfe11cca88e5c54518c4880d88d40a50bd753d64e783569fd`；假设核对 `b5a261f441295c9039c86f78925190c525d318a273226299df8264fc499e6734`。报告绑定配置、输入、预测及诊断，已离线重放核验。原始产物默认被 Git 忽略，源码克隆不等于完整实验包；复核需取得对应材料，不能只靠哈希重现原文。

## 已交付能力与当前边界

- **可运行应用：** Web 工作台、公开 Fixture、真实 Hy3 配置入口、结果与证书导出；[启动说明](../README.md#快速体验)要求 Python 3.11+，真实模式另需服务配置和 Docker。
- **可审计评估：** 需求／步骤／原文引用绑定，定位类型与行号校验，有限请求预算、断点续跑、逐次脱敏失败诊断；新定位实现相关 **117 项测试通过**，不等于全套件通过。
- **可解释结论：** 能发现测试结论之外的过程问题；同时公开漏检、定位不足与不稳定性。历史外部代码功能成绩及难度分层见 [README 历史实验](../README.md#历史外部任务增强测试揭示遗漏代码判断仍需降低误报)，不作为过程定位成绩。
- **尚未完成：** 81 条保留集继续封存，没有保留集成绩；其“保留”指在过程标注／调优闭环之外，父题存在历史生成暴露。[冻结说明](experiments/process-heldout-v1.md)。新版 86 秒工作台录屏已接入，干净目录验收及提交包完整性仍需完成。

项目的核心贡献是把过程判断、错误定位和证据组织成可检查的工作流，并检验它何时有效、何时失败；现有结果不支持“复杂方法始终更优”或普遍泛化的结论。
