# 两个典型过程案例（2026-09-10）

在工作台顶部点击“重点案例”，或切换到“典型案例”页的两个案例按钮。启动服务后可直接打开：

- `http://127.0.0.1:8765/?case=tuple_str_int`
- `http://127.0.0.1:8765/?case=find_char_long`

支持附加 `&recording=1`。已有服务需重启以加载新 API；仅刷新浏览器不会更新 Python 服务。只读预览可在仓库根目录运行 `./scripts/run_recording_demo.ps1 -Offline -Port 8767`，相应把上述地址端口改为 8767。

## 展示顺序

1. `tuple_str_int`：先展示历史官方 base / plus 均通过，再对照原解答承诺支持 `"(5,)"` 与 L5 的整数转换。静态推演表明尾随逗号产生空字符串；这不是新增的执行证据。原代码与原计划一致，审核归为 P01 推理层算法错误，首错位置在边界说明，步骤为 null。标签属于预测后单人 AI 辅助复核，非独立盲审。
2. `find_char_long`：对照计划 S2 中 `>= 4` 与代码 L2 中 `> 4`，展示 A01 对齐层失配。该例是构造探针，变异代码未执行，功能证据不可用。展开既有两方法判断，可见两者引用代码 L2，但首错步骤均为 null；不得将代码定位计为步骤或精确位置命中。
3. 按需展开“完整解答原文与审核定位”“证据来源与 SHA-256”，打开审核说明或下载案例 JSON。

两例独立于原有三个公开 Fixture 和所有聚合计分，不增加样本分母，不修改冻结标签、预测或报告。

## 数据与核验

发布摘录：[featured_process_cases_v1.json](../releases/featured_process_cases_v1.json)。只包含这两例所需的公开需求、解答、选定审核字段、功能汇总及探针既有判断；不依赖本机绝对路径，不包含标注者身份或保留集内容。

`scripts/build_featured_process_cases.py` 离线导出，检查标注包 manifest、标签修订配置和预测运行报告中的字节哈希，并核对功能结论绑定的代码哈希及引用原文。持有对应原始材料时可执行 `python scripts/build_featured_process_cases.py --check` 重新核对，不调用模型、不执行候选代码。

运行时固定绑定发布摘录的规范化 JSON SHA-256。原始材料存在时还核对其规范化内容哈希，允许 Git 换行转换；缺少原件时明确标为“展示已发布摘录”，不声称重新核验原件。发布摘录篡改或现存原件内容漂移时 API 返回 503，页面拒绝展示。两个审核文档通过固定白名单只读提供，任意路径及查询参数不接受。

## 验证

针对性测试覆盖发布摘录独立加载、来源漂移、内容篡改、换行转换、HTTP 路径边界，以及两例的证据与定位口径。页面验证覆盖直接链接、案例切换、桌面与窄屏高亮、详情展开和不可用状态；不触发模型请求。

本次实测：`test_demo_featured_cases.py` 与现有 demo app、current validation、comparison、ablation 五个测试文件共 83 项通过；Ruff check / format 通过。Chrome 验证通过 1440px 与 390px 布局、两个直接入口、不刷新页面的视图切换、来源文档和 503 拒绝态，无页面脚本异常，浏览器仅发起本机 GET 请求。首次沙箱测试受 Windows 临时目录权限限制，解除该执行限制后同组测试通过；未以此替代全套件验证。
