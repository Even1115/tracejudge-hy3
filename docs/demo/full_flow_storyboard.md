# TraceJudge-Hy3 全流程展示与录制脚本

本次交付包含展示流程、现有工作台的逐幕录制模式，以及离线预演验证。正式视频建议控制在 **118 秒以内**，展示一次完整的解题与过程评估，最后补充一个公开对照案例和已发布实验结果。

演示主线：**题目 → 解题说明与代码 → 实际测试 → 四层对齐 → 首错定位 → 反例与证书 → 过程错误对照 → 实验验证**。

## 1. 启动与入口

Windows PowerShell，在仓库根目录运行：

```powershell
# 离线预演：仅在本次服务进程禁用 Hy3，使用独立演示环境。
.\scripts\run_recording_demo.ps1 -Offline -Port 8765

# 真实 Hy3：自动检查 Docker，必要时启动 Docker Desktop 并等待引擎就绪。
.\scripts\run_recording_demo.ps1 -Port 8765
```

脚本依次查找 `.venv/Scripts/python.exe`、`artifacts/demo-preview-env/Scripts/python.exe` 和 PATH 中的 Python。需 Python 3.11+ 及项目依赖；启动服务前会做 readiness 检查，缺少依赖时停止，不自动安装依赖。

Windows 正常模式会复用已运行的 Docker；未就绪时尝试启动已安装的 Docker Desktop，默认等待 120 秒，可用 `-DockerWaitSeconds 240` 延长。支持系统安装与当前用户的 `Programs\DockerDesktop` 安装目录，自动为本次服务补充 Docker CLI 的 PATH。首次安装的交互设置需在 Docker Desktop 中完成；未安装或超时会明确报错。`-Offline` 跳过 Docker 检查与启动。退出演示服务后 Docker 保持运行。

重复执行启动命令时，如果该端口已有符合请求模式的可用演示服务，脚本直接显示现有地址并返回，保留已有运行结果。正常模式仅复用 HY3 可用的服务；`-Offline` 仅复用明确标识为离线的服务。若端口被其他程序占用或现有服务模式不符，会提示在原终端停止旧服务，或用 `-Port 8766` 选择其他端口，不自动结束任何进程。

macOS / Linux 使用已有入口：

```bash
./scripts/run_recording_demo.sh
```

- 普通工作台：[http://127.0.0.1:8765/](http://127.0.0.1:8765/)
- 全流程录制：[http://127.0.0.1:8765/?recording=1](http://127.0.0.1:8765/?recording=1)

页面不会自动调用模型。选择模式并点击“开始评估”才会启动一次运行。Windows 正式录制时去掉 `-Offline`，由服务端既有配置决定真实 Hy3 是否可用。不要在当前正式评测使用的 Python 环境中升级依赖。

### 效果与成本（可选第 9 幕）

页面顶部点击“效果与成本”，或在录制流程中点击“9 成本”。原八幕仍可独立录制；若加入成本展示，建议从前面的讲解中压缩 10–15 秒，保持比赛视频时长限制。

- **单条样本**：新 Demo 分开记录 Solver 与 Judge 的输入／输出 token、模型请求耗时、阶段耗时、调用次数与重试次数。可展开逐次请求，结果 JSON 包含完整明细，HTML 报告包含分项汇总。
- **评测总耗时**：排除 Solver 生成，包含静态检查、测试执行、Judge、反例与证书重放。样本总耗时覆盖流水线及重放，不包括服务启动检查和产物写入；模型请求耗时只计 API 等待。
- **失败和缺失**：失败请求也保存，重试包含同一阶段的再次请求与 JSON 修复；未返回的 usage 显示“未返回”，并保留已知用量及覆盖率。Fixture 没有模型请求，因此调用与 token 为 0，本地执行时间仍实测。
- **持久化**：新请求逐条追加到 `artifacts/demo_costs/<sample_id>.jsonl`（如设置了 `TRACEJUDGE_ARTIFACT_DIR`，则位于该目录下）。完成记录绑定对应结果产物；失败运行也保留已产生的记录。强制中断时可能只有部分日志，不应当作完整统计。
- **五方法对照**：读取已发布的 `phase3_research_report_public_v1.md`，同表显示检测准确率、有效判断数、已知 token 与覆盖行数、实际调用／JSON 修复、逐配对耗时累计。这里是固定 57 条样本的 Judge 成本，不包含共享 Solver，不能视为新 Demo 的五方法对比或全部基准的最新成绩。
- **历史边界**：不反推旧 Demo 的缺失 token，不把累计配对耗时解释为并行实验墙钟时间，不从 token 估算金额；Test-only 复用已保存测试结果，其表中 0 秒不代表重新执行测试的开销为 0。

这项新增采集仅用于通过页面发起的新 Demo；既有正式实验入口和冻结报告保持原统计口径。

## 3. 八幕脚本（118 秒）

以下时间是剪辑后的成片时间，不是系统性能测量。实际模型等待可以压缩，在画面注明“等待过程已剪辑”，保留本次运行实际耗时。

| 成片时间 | 操作与画面 | 建议字幕／旁白 |
| --- | --- | --- |
| 0–10 秒 | 第 1 幕，展示 safe_mean 的需求和输入约束。选择运行模式，点击“开始评估”。 | 给定明确需求，Hy3 生成解题说明与代码，TraceJudge 检查它们是否相互支持。 |
| 10–28 秒 | 完成后自动进入第 2 幕。查看需求理解、实现步骤和代码。 | 我们评估的是模型输出的解题说明与实现计划，不是模型内部思维。 |
| 28–42 秒 | 下一幕进入“测试”。展示用例输入、预期结果和实际输出。 | 首先执行代码，用测试检查实际行为。当前结果只覆盖这些已执行用例。 |
| 42–52 秒 | 下一幕进入“对齐”。结合需求、解释、代码与静态证据。 | 然后检查解题说明与实现是否一致，结构特征仅作为辅助证据。 |
| 52–72 秒 | 下一幕进入“定位”。展示功能与过程结论、首错步骤、关联需求、原始代码范围。 | 判断分别落到功能、过程和定位；代码高亮保留评估器给出的原始范围。 |
| 72–88 秒 | 下一幕进入“证书”。查看反例、证书等级和自动重放结果。可点击下载错误证书。 | 对有执行证据支持的失败，保存可复查证据，并独立重放失败输入。 |
| 88–104 秒 | 下一幕进入“对照”。说明与代码并排，保留公开构造案例标识。 | 这条公开对照的代码没有改变，但说明声称取最大值。测试通过，仍不能证明说明成立。 |
| 104–118 秒 | 下一幕进入“验证”。上半屏为“历史阶段四冻结研究 · 57 条轨迹”，下半屏为“2026-09-10 最新补充验证”三张小卡；展示分子分母、复标情况、限制说明和报告来源。 | 单个案例用于解释机制；方法有效性来自另行冻结的配对实验和人工核验。历史冻结结果与最新补充验证分列展示，不合并排名。 |

## 4. 实际操作

1. 使用 1440×900 或 1920×1080 浏览器窗口，100% 缩放；先确认中文与代码清晰。
2. 打开录制链接。第 1 幕默认显示公开题目。未运行时，第 2–6 幕不可点击；公开对照与已发布验证可以单独查看。
3. 离线排练选择“公开可复现 Fixture”。真实录制选择“真实 Hy3”；不可用时先解决页面提示，不把 Fixture 当作真实调用。
4. 点击“开始评估”，保留运行开始画面。完成后自动停在第 2 幕，按“下一幕”或键盘右方向键推进；左方向键返回。聚焦模式单选框时，方向键保留原生选择行为。
5. 第 5 幕查看高亮步骤和代码。代码范围可能是整个函数，不能配上“精准定位这一行”的字幕。
6. 第 6 幕展示实际重放结果。重放已由后端执行完成，当前界面没有“点击再重放”按钮，不应在旁白中虚构该操作。
7. 第 7 幕明确切换为已冻结公开对照；第 8 幕上半屏为历史阶段四冻结研究（57 条轨迹），下半屏为 2026-09-10 最新补充验证卡片（含限制说明与“成果总览（只读）”入口）。右侧保留本次运行配置与导出入口。
8. 下载本次结果 JSON／HTML，以及存在时的证书 JSON，用 Run ID 将录屏与产物对应起来。

## 5. 真实 Hy3 没有犯错时怎么办

正确结果同样完成了题目、解答、测试和过程评估。保留“未发现问题／未产生证书”的实际画面；不要改写结果来制造错误。

如果正式视频还需展示可重放错误证书，可另外录制一段 **公开 Fixture** 的第 5–6 幕，并在剪辑中用明确字幕“以下切换到公开构造边界错误案例”。用它替换或压缩相应时段，保持总时长小于 2 分钟。真实 Hy3 片段和 Fixture 片段保留各自的来源与 Run ID。

代码正确但解释错误的 reasoning_swap，展示的是说明与代码的矛盾，不能宣称存在一个让正确代码功能失败的反例。等价实现案例中的人工构造标签也不能冒充系统当次正确识别。
