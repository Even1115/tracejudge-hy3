# 60 秒看懂项目 · 四站导览说明

面向评审的只读导览，目标是在约一分钟内讲清：项目解决什么问题、定位能力、证据链与实验边界。60 秒是建议阅读时长，导览不倒计时、不自动跳转，由讲解者或评委手动推进。

## 入口

- 工作台任意页面右上角「60 秒看懂项目」按钮（普通模式与 `?recording=1` 录制模式均可见）。
- 直接链接：`http://127.0.0.1:8765/?tour=1`（以实际启动端口为准）。
- URL 参数优先级：`tour=1` 优先于 `case=`（导览会自行选择案例，`case=` 不再生效）；`recording=1` 可与两者同时存在。录制模式下，九幕控制条在导览期间隐藏、退出导览时恢复，两套控制栏不会同时出现。

## 操作

- 「上一步 / 下一步 / 退出导览」按钮；键盘 `←` / `→` 切站，`Esc` 退出。
- 退出后恢复进入导览前的页面、重点案例、公开 Fixture 选择、重点案例的证据展开状态、录制幕次与滚动位置；等待展开区域布局完成后再恢复滚动，焦点返回入口时不滚动页面。迟到的案例请求不能覆盖恢复状态；不停止正在进行的运行，也不启动新运行。
- 每站自动滚动到对应证据并加青色描边；加载失败时显示真实不可用提示，仍可前进或退出。

## 四站讲解建议

1. **tuple_str_int：测试通过，过程承诺仍可能有问题**
   官方测试通过，并不证明解答中的每项承诺都成立。
   指向重点案例中高亮的「(5,)」边界承诺与相关代码 L5。强调这是静态推演摘录（未新增执行），标签为预测后 AI 辅助复核，完整限制说明就在证据区内。
2. **find_char_long：把计划—代码失配落到具体位置**
   系统把计划与代码的差异关联到具体步骤和代码位置。
   指向构造探针中并排的计划 S2「>= 4」与代码 L2「> 4」。说明这是构造探针；审核金标 S2 与模型实际代码定位 L2 是两种口径，不宣称步骤或精确位置命中。
3. **已有证书重放结果：判断需要可核查证据**
   有执行支持的错误，可以保存反例并核查已有重放结果。
   选中历史公开案例 boundary_deletion，再定位下方回归卡片的“反例重放”指标。使用 `/api/regression` 读取的历史回执汇总，展示实际计数、回执 ID 和来源路径；回执为 `docs/releases/phase4/phase4_public_replay_receipt_v1.json`，与公开案例的来源哈希绑定。只有回执汇总可用且身份字段完整、来源匹配时才展示该记录；回执不可用时显示“证书重放结果暂不可用”，已有案例说明不充当重放证据；有效记录为 0/1 时显示“未确认失败复现”，不当作成功。导览只读取已有结果，不启动评估、模型调用或候选执行。
4. **最新验证：说明能力与边界**
   检测、精确定位与稳定性分别验证，结果同时披露收益和不足。
   指向「2026-09-10 最新补充验证」区域：36 条开发集重计分、五轮冻结消融重复、3 条构造定位探针分卡列示，各自口径独立，不合并分母、不设总排行榜；上方历史 57 条冻结研究与其分列。

## 证据限制

- 导览不复制数据、不硬编码实验数字；所有内容来自页面既有的哈希校验组件（重点案例摘录、公开 showcase、最新补充验证卡）。
- 任一来源未通过校验时，导览显示不可用提示并保留原有失败关闭行为，不把静态推演包装为执行证据，不读取封存保留集。
- 导览不触发 `POST /api/run`，不调用模型，不执行候选代码（`tests/test_demo_tour.py` 有静态守卫）。

## 行为回归验证

`tests/browser/demo_tour.spec.cjs` 使用真实 Chrome DOM 覆盖退出恢复、普通／录制模式、四站切换、来源有效及不可用分支（503、缺少回执身份、来源不匹配、未确认复现）、退出后的迟到请求及 390px 窄屏。测试拦截所有非本机 GET 请求，不启动评估。

先启动本机离线服务（默认测试端口 8770），在已具备 Node.js、Playwright 和 Chrome 的环境运行：

```powershell
$env:TRACEJUDGE_DEMO_URL = 'http://127.0.0.1:8770'
$env:TRACEJUDGE_CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
node --test tests/browser/demo_tour.spec.cjs
```

如 Playwright 位于共享依赖目录，通过 `NODE_PATH` 指向包含 `playwright` 包的 `node_modules`。未设置 Chrome 路径时使用 Playwright 已安装的 Chromium。

本次修复验证：9 项浏览器行为测试通过；原有 demo/tour/featured/current-validation/comparison/ablation 六个测试文件共 88 项通过。针对性通过不代表全套件通过。
