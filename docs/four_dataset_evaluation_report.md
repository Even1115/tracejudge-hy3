# TraceJudge-Hy3 四数据集测试报告

报告版本：`four-dataset-interim-v1`。汇总核验截至：**2026-09-06 21:40:09（北京时间）**。

状态：**四个数据集均已纳入；HumanEval+、MBPP+ 120 和 CodeJudge-Eval 约定轮次已完成，LiveCodeBench 尚有两题服务异常，`complete=false`。** 本报告是阶段性综合结果，不将“报告收齐”写成“全部题目完成有效评测”。

## 摘要

本报告汇总 Hy3 在 HumanEval+、MBPP+、LiveCodeBench 与 CodeJudge-Eval 上的现有实验。前三组考察代码生成的功能正确性，第四组考察对数据集提供代码的 judge-only 判断能力。所有指标沿用各自冻结协议，分别保留选题分母、实际有效样本数和失败类型，不生成跨任务的总平均准确率。

HumanEval+ 全量 164 题的 Base+Extra 通过率为 **157/164（95.73%）**；MBPP+ 固定 120 题子集为 **95/120（79.17%）**。LiveCodeBench 固定 60 题当前通过 **53/60（88.33%）**，58 题已有有效执行，另两题经恢复重试后仍为 Provider 失败。CodeJudge-Eval v3-A 在 60 个正确、60 个错误程序的平衡样本上取得 **90.00% balanced accuracy**；v3-B 的三个标签粒度条件下，功能判断准确率均为 98.00%，原生标签 exact-match 分别为 96.00%、84.00% 和 72.00%。

增强测试在 HumanEval+ 和 MBPP+ 中分别发现 6 个、22 个 Base 已通过但 Base+Extra 未通过的候选。Judge 的错误检出率较高，但对正确程序仍存在误报，且细粒度标签判断与功能判断之间存在差距。这些证据覆盖生成正确性与外部代码判断，尚不直接验证过程错误定位、首错步骤或错误证书重放能力。

### 2.2 模型与失败处理

主要模型请求标识为 `tencent/hy3`，记录的 reasoning effort 为 `high`，Provider timeout 为 120 秒，额外重试预算为 2。生成任务沿用最多 1 次结构化解析修复预算。CodeJudge v3 的记录另明确指定 temperature=0；不能推定未显式记录的生成参数也与其相同。完整非敏感配置见[配置汇总](evaluation_release/2026-09-06-four-datasets-v1/configurations.json)。

生成任务每题保留一份成功解析的候选，允许既定的服务重试和解析修复；成功生成不等于通过测试。有效的错误答案、编译错误、候选异常和官方超时均保留，不为提高分数重跑。Provider 失败、解析失败与执行器基础设施失败分开统计。

HumanEval+/MBPP+ 使用固定 EvalPlus 执行 Base 和 Extra；Base+Extra 指两组均通过。LCB 通过固定官方 checker 在 Linux 容器中执行公开与隐藏测试。生成消息只使用公开信息，隐藏测试不进入生成 Prompt。CodeJudge 候选由数据集提供，没有在该实验内生成新代码，也没有 Hy3 原生解题轨迹。

## 6. CodeJudge-Eval：外部 judge-only 判断

### 6.1 v3-A：平衡功能正确性判断

120 个候选中，gold 正确与错误各 60 个。**以“错误程序”为阳性**，混淆矩阵如下：

| Gold / 预测 | 预测错误 | 预测正确 | 合计 |
| --- | ---: | ---: | ---: |
| 错误程序 | TP = 59 | FN = 1 | 60 |
| 正确程序 | FP = 11 | TN = 49 | 60 |

| 指标 | 结果 |
| --- | --- |
| 有效判断 | 120/120；最终 Provider/解析失败为 0 |
| Balanced accuracy（主指标） | **90.00%**；分层候选 bootstrap 95% 区间 [85.00%, 95.00%] |
| 原始 accuracy | 108/120 = 90.00%；与 balanced accuracy 相同源于本轮 gold 恰好平衡 |
| 错误检出率 / sensitivity | 59/60 = 98.33% |
| 正确程序放行率 / specificity | 49/60 = 81.67% |
| 正确程序误报率 / FPR | 11/60 = 18.33% |
| 错误程序漏报率 / FNR | 1/60 = 1.67% |
| Precision / F1 / MCC | 84.29% / 0.9077 / 0.8113 |
| 多数类基线 | accuracy 和 balanced accuracy 均为 50.00% |

主要问题是将部分正确程序判为错误，不能只用 98.33% 的检出率宣称判断可靠。Bootstrap 使用既定 10,000 次重采样与 seed `20260907`；本次引用既有区间，没有重新运行模型或重算全部逐候选 bootstrap。

### 6.2 v3-B：同一候选的三种输出粒度

这里的 easy/middle/hard 表示**输出标签的粒度条件**，不是 LCB 的题目难度分层。三个条件使用相同 50 个候选，共 150 条有效判断。

| 标签条件 | 有效判断 | 二元功能判断准确率 | 原生标签 exact-match |
| --- | --- | --- | --- |
| easy | 50/50 | 49/50（98.00%） | 48/50（96.00%） |
| middle | 50/50 | 49/50（98.00%） | 42/50（84.00%） |
| hard | 50/50 | 49/50（98.00%） | 36/50（72.00%） |

三组两两功能判断均为 50/50 一致；McNemar 不一致对数均为 0，原始及 Holm 校正后的 p 值均为 1。未观察到功能判断差异不等于证明条件等效；样本中重采样得到的 [0, 0] 差值区间也不是总体零差异的证明。

原生标签空间随条件变化，exact-match 的 96% → 84% → 72% 只作为当前样本中细粒度表达更难的次要证据，不与二元功能准确率混用，也不视为同一标签空间下的直接性能排名。

### 6.3 保留历史轮次及评分修订

full-v1 有 90 个候选，仅 4 个 gold 正确，其 raw accuracy 为 86/90 = 95.56%，与永远预测非 AC 的多数类基线相同；修订后的 balanced accuracy 为 85.76%。旧版不兼容标签空间的 macro-F1 不作为主结论。

v3-A 原断网轮有 116/120 个有效判断、4 个 Provider 失败，固定分母 balanced accuracy 为 88.33%；随后完整轮为 120/120、90.00%。两轮分别保存，不将它们拼接成更大独立样本，也不将差值解释为模型能力提升。完整 v3-A 和 v3-B 是本报告的主分析，历史结果保留于[机器可读汇总](evaluation_release/2026-09-06-four-datasets-v1/results.json)。

## 9. 结论与局限

当前证据支持三项具体结论：其一，固定 Hy3 候选在 HumanEval+、MBPP+ 与 LCB 已执行部分取得了可量化的功能通过结果，扩展测试确实增加了错误检出；其二，CodeJudge 平衡样本上的二元功能判断达到 90.00% balanced accuracy，但正确程序误报仍有 18.33%；其三，细粒度标签判断的表现与功能判断不同，不能用高二元准确率替代错误类型归因验证。

本报告不支持官方完整排行榜认证、不支持 MBPP+ 378 题或完整 LCB 成绩、不提供训练数据无污染保证，也不验证过程首错定位、证书重放与完整系统闭环。每题单份可用候选与既有服务重试不等于重复生成实验；当前区间不能衡量全部模型随机性。相同模型别名也不能保证不同时间与供应商始终使用相同远端权重。

两道 LCB Hard 题缺少有效答案，故四数据集整体仍标为阶段报告。后续应先核实约 300 秒取消的来源，再按原身份与恢复规则补齐允许重试项；不改分母、不把有效失败重跑到通过、不将跨协议结果静默混合。成本和耗时缺少统一、完整的跨机器计量，本报告不计算总成本、平均速度或跨数据集综合分数。
