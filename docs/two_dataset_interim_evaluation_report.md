## 摘要

本报告汇总 TraceJudge-Hy3 在 HumanEval+、MBPP+ 与 CodeJudge-Eval 上的阶段性外部评测。
三个数据集涵盖两类问题：HumanEval+ 与 MBPP+ 评估模型从公开函数题面生成可执行代码的能力，
CodeJudge-Eval 则在给定候选代码的 judge-only 条件下评估模型识别功能错误及错误类别
的能力。两类指标不在同一任务空间中，不能求平均或直接比较高低。

CodeJudge-Eval 的平衡 holdout 实验 v3-A 覆盖 120 个候选，完整运行取得 90.0%
balanced accuracy（95% bootstrap CI [85.0%, 95.0%]）。模型对错误程序的检出率为
98.3%，但对正确程序的 specificity 为 81.7%，即 60 个正确程序中有 11 个被误报
为错误。v3-B 对 50 个相同候选分别施加 easy、middle、hard 三种输出粒度，共 150
次有效调用。三种条件的功能正确性准确率均为 98%，两两功能判断完全一致；但原生
标签 exact-match 随粒度升高从 96% 降至 84% 和 72%。结果表明，当前 Hy3 的二元
功能判断强且较稳定，而细粒度、尤其复合执行结果的归因仍是主要瓶颈。

HumanEval+ 完整 164 题现已全部生成、解析并取得有效 EvalPlus 执行结果：
Base 通过 163/164（99.39%），Base+Extra 通过 157/164（95.73%），基础设施错误为 0。
结果由原 161 条有效执行、已核验的 103/104 两题诊断执行及缓存修复后的第 15 题
补充执行组成，原文件和候选代码均保持不变。该结果是跨批次汇总的全量单候选通过率，
不是官方排行榜认证。既有 45 题子集的端到端 Base+Extra 40/45（88.9%）保留为历史
证据，不与全量 164 题相加作为独立样本。

MBPP+ 固定 120 题子集已全部成功生成并取得有效执行结果，最终 Provider/解析错误和
基础设施错误均为 0。Base 通过 117/120（97.50%），Base+Extra 通过 95/120
（79.17%，Wilson 95% CI [71.05%, 85.47%]）；增强测试额外暴露 22 个 Base 已通过
但 Base+Extra 未通过的候选。运行中曾有 3 次 Provider 失败，均经重试恢复；2 个
官方测试超时计入功能未通过，不属于基础设施故障。本结果只描述预先冻结的 120 题，
不能写成完整 378 题成绩，也不直接验证过程错误定位能力。

## 2. 任务定义与不可比较边界

### 2.1 HumanEval+

HumanEval+ 属于 `function + generation` 任务。模型只看到公开题面、函数签名和入口
点；标准答案、Base/Extra 测试和失败输入不进入生成 Prompt。阶段一指标反映生成
覆盖、结构化解析和 Provider 稳定性；只有阶段二官方 EvalPlus 执行才能产生 Base、
Base+Extra 和端到端功能通过率。

### 2.2 CodeJudge-Eval

CodeJudge-Eval 属于 `standard_io + judge_only` 任务。候选代码由数据集提供，Hy3
负责判断代码是否功能正确，并在条件允许时判断 CE、WA、RE、TLE 或复合执行结果。
数据集不包含 Hy3 原生解题轨迹，因此本报告不计算过程正确率、首错步骤定位或错误
证书重放率。

### 2.3 跨数据集解读规则

- HumanEval+ 与 MBPP+ 衡量“生成的代码能否通过测试”，CodeJudge-Eval 衡量“模型能否判断
  给定代码是否正确”；两者不是同一个 accuracy。
- 不对三个数据集的百分比求平均，不据此建立统一排行榜。
- 生成成功不等于功能正确，标签 exact-match 也不等于功能正确性判断。
- Provider/解析/执行器失败必须单独报告，不得静默从分母删除。

### 2.4 MBPP+

MBPP+ 属于 `function + generation` 任务。模型使用公开题面和函数入口信息生成
一份候选；官方 Base/Extra 测试、标准答案和失败输入不进入生成 Prompt。当前实验
从固定版本的 378 题集合中预先选择 120 题，先冻结选择，再生成并执行；本报告同时
报告生成覆盖、条件执行通过率和来源 cohort 端到端通过率，不把生成成功视作答题正确。

## 4. CodeJudge-Eval 结果

### 4.1 证据演进

full-v1 首先完成 90 条外部迁移，但 gold 仅有 4 个 AC，raw accuracy 95.6% 与
永远预测非 AC 的 majority baseline 完全相同。修正评分后 balanced accuracy 为
85.8%，但 specificity 只有 4 个样本，无法可靠估计误报率。该限制直接推动了两个
预注册 holdout：v3-A 使用 60 AC + 60 非 AC 的平衡设计，v3-B 使用同一候选三条件
配对设计。full-v1 的公开修订指标见
[汇总摘要](evaluation_release/2026-09-06/results.json)中的 `codejudge_eval.experiments.full_v1_corrected`，v3 设计见
[v3 预注册协议](codejudge_eval_v3_protocol.md)。

### 4.2 v3-A：平衡功能正确性判断

完整恢复性重跑 `v3a-20260905T103721Z` 包含 120/120 有效判断，无 Provider 或
解析失败。主指标按固定 60/60 gold 分层计算。

| 指标 | 结果 | 95% CI/说明 |
| --- | ---: | --- |
| Balanced accuracy | 90.0% | bootstrap [85.0%, 95.0%] |
| Accuracy | 108/120 = 90.0% | Wilson [83.3%, 94.2%] |
| Sensitivity（检出错误程序） | 59/60 = 98.3% | Wilson [91.1%, 99.7%] |
| Specificity（放行正确程序） | 49/60 = 81.7% | Wilson [70.1%, 89.4%] |
| FPR（正确程序误报） | 11/60 = 18.3% | Wilson [10.6%, 29.9%] |
| FNR（错误程序漏判） | 1/60 = 1.7% | Wilson [0.3%, 8.9%] |
| Precision | 84.3% | valid prediction diagnostic |
| F1 | 90.8% | valid prediction diagnostic |
| MCC | 0.811 | valid prediction diagnostic |

混淆矩阵为 TP=59、TN=49、FP=11、FN=1。模型几乎不会放过错误程序，但会把约
18% 的正确程序误判为错误。对代码审查辅助场景，这表现为高召回、偏保守的 Judge；
若用于自动拒绝提交，仍需要官方执行或人工复核降低误报成本。

分 gold 类型的功能判断准确率为：CE 12/12、MIXED 12/12、RE 12/12、TLE 12/12、
WA 11/12、AC 49/60。每个错误子层仅 12 题，分层结果属于描述性证据。

#### 断网轮与完整重跑

原运行 `v3a-20260905T083333Z` 为 116/120 有效，4 个 Provider 错误按预注册规则
保留在全分母中，balanced accuracy 为 88.3%（95% bootstrap CI [82.5%, 93.3%]）。
完整重跑为 90.0%，两个区间高度重叠，不能解释为模型性能提升。

在两轮共同有效的 116 个候选上，功能判断一致 114/116（98.3%），原生 verdict
一致 111/116（95.7%），细粒度派生标签一致 107/116（92.2%）。因此完整重跑作为
基础设施恢复与稳定性补充证据保留，不能无痕替换原始预注册运行。

### 4.3 v3-B：标签粒度配对实验

运行 `v3b-20260905T120255Z` 对 50 个相同候选分别使用 easy、middle、hard 三种
独立输出空间，Latin-square 平衡调用位置，共 150/150 有效判断。

#### 功能正确性主结果

| 条件 | 准确率 | Wilson 95% CI |
| --- | ---: | ---: |
| Easy | 49/50 = 98.0% | [89.5%, 99.6%] |
| Middle | 49/50 = 98.0% | [89.5%, 99.6%] |
| Hard | 49/50 = 98.0% | [89.5%, 99.6%] |

三个条件两两功能判断一致率均为 50/50，McNemar 原始与 Holm 调整 p 值均为 1.0，
配对准确率差均为 0。唯一功能错判是同一个 gold RE 候选在三个条件下均被判为 AC，
说明该错误并非由输出粒度变化触发。

严谨结论是：在这 50 个候选上没有观察到粒度改变二元功能判断的证据。由于预注册
功效分析表明 N=50 的 McNemar 检验功效有限，不能把 p=1.0 写成“证明三种粒度完全
等效”。

#### 细粒度标签次结果

| 条件 | 原生标签 exact-match | Wilson 95% CI |
| --- | ---: | ---: |
| Easy | 48/50 = 96.0% | [86.5%, 98.9%] |
| Middle | 42/50 = 84.0% | [71.5%, 91.7%] |
| Hard | 36/50 = 72.0% | [58.3%, 82.5%] |

| 配对差 | 点估计 | 候选级 bootstrap 95% CI |
| --- | ---: | ---: |
| Easy − Middle | +12 个百分点 | [4, 22] |
| Easy − Hard | +24 个百分点 | [12, 36] |
| Middle − Hard | +12 个百分点 | [4, 22] |

三组次指标呈单调下降，说明更细的输出空间主要增加了错误类别精确归因难度，而没有
破坏二元功能判断。Hard 条件的 execution-outcome 集合 exact-match 为 33/45 =
73.3%（Wilson 95% [59.0%, 84.0%]）。小样本描述性分层中，TLE 为 5/5、WA 为
4/5、RE 为 2/5、RE+TLE 为 1/5；包含 RE 的复合错误是当前最明显的困难，但每层
仅 5 题，不作确认性推断。

### 5.3 失败、恢复与解释边界

生成阶段累计 123 次记录在案的尝试：120 次成功、3 次 Provider 失败；
`Mbpp/16`、`Mbpp/432`、`Mbpp/456` 各经一次重试恢复，parse repair 为 0。
最终错误数为 0 不等于过程中没有网络或 Provider 异常。

`Mbpp/267`、`Mbpp/765` 的 Base 通过、Extra 为官方 `timeout`，对应基础设施状态
均为正常。这两题是固定测试限时下的有效未通过，不应作为断网失败被删除或选择性
重跑。另 23 个 `fail` 在固定官方输出格式中不能可靠细分为错误答案或候选异常；
本报告不据此声称已经识别具体算法根因。

**95/120 是固定 120 题子集的单候选成绩，不是完整 378 题成绩。** Wilson 区间
用于描述当前题目级比例的不确定性，不是全量 378 题成绩已落在该范围的证明，
也未估计重复生成的方差。公开基准可能受训练数据污染或记忆影响；本轮结果不构成
官方排行榜认证，更不直接验证 TraceJudge 的过程错误定位、首错步骤或证书重放能力。

## 6. 跨实验综合解读

现有证据支持把 TraceJudge-Hy3 的能力拆为三个层次：

1. **代码生成与功能执行**：HumanEval+ 完整 164 题均取得可解析候选和有效执行，
   Base 通过 163/164，Base+Extra 通过 157/164；MBPP+ 固定 120 题也均有效执行，
   Base 通过 117/120，Base+Extra 通过 95/120。这些指标描述各自固定候选的功能正确性，
   不将数据集间的差异单独归因为难度、Prompt 或模型泛化能力。
2. **功能错误筛查**：CodeJudge-Eval v3-A 在平衡 holdout 上取得 90.0% balanced
   accuracy，错误检出率 98.3%；v3-B 三条件均为 98%，说明二元判断较稳定。
3. **细粒度诊断**：v3-B 从 easy 96% 下降至 hard 72%，Hard execution-outcome
   exact-match 为 73.3%，说明“发现有错”明显容易于“准确说明是哪一种或哪几种错”。

最适合当前证据的总体表述是：

> TraceJudge-Hy3 在外部候选代码上表现出较强、跨 Prompt 粒度稳定的功能错误检测
> 能力；其主要判别弱点是对正确程序的误报，主要诊断弱点是复合执行结果的细粒度
> 归因。HumanEval+ 全量单候选 Base+Extra 通过率为 157/164（95.73%）；MBPP+ 固定
> 120 题子集为 95/120（79.17%），两轮功能执行覆盖均完整，但后者不是 378 题成绩。
> 以上证据覆盖代码生成正确性与 judge-only 外部判断，不等同于
> TraceJudge 的过程错误定位等全部能力已经验证。

## 7. 统计与解释边界

- v3-A 是人为平衡的 50%/50% holdout，适合估计 sensitivity、specificity 和
  balanced accuracy，但其 precision 不能直接外推到真实世界错误基率。
- v3-A 完整重跑发生在查看受断网影响结果之后，属于恢复性重复实验；两轮都必须
  保留，不能选择性报告较高的一轮。
- v3-B 功能比较使用预注册的三组配对 McNemar 检验和 Holm 校正；p=1.0 表示没有
  观察到差异，不表示统计等效。
- v3-B 标签 exact-match 差和 bootstrap 区间属于次指标，不替代功能判断主结果。
- HumanEval+ 45 题条件通过率 40/42 必须与端到端 40/45 并列，避免只分析成功生成
  候选造成 survivorship bias。
- HumanEval+ 164 题结果每题只有一份固定候选，未估计重复生成方差；全量结果跨批次
  汇总，第 15 题使用压缩缓存，耗时不能直接用于严格性能比较。
- 45 题历史子集与 164 题全量集合不是独立数据集；不将二者相加扩大样本量。
- MBPP+ 为预先冻结的 120/378 子集，不按结果重选题目；若扩展全量，保留本轮全部
  成功与未通过结果，不因分数高低决定提前停止或替换候选。
- MBPP+ 的 2 个官方测试超时计入功能未通过，不归入基础设施错误；3 次生成阶段
  Provider 重试须保留审计记录，不能把最终成功覆盖解释为零异常调用。
- 不把不同任务、不同样本和不同分母的百分比直接比较或合并。
- 本报告没有提供过程错误定位、首错步骤定位、错误证书重放或完整系统闭环的
  专项评测结果；“两类评测完成”不能扩展为“全部能力验证完成”。

### 7.1 统计谬误扫描

覆盖 11/11：未发现 Simpson 方向反转或个体/群体层次混淆；没有协变量控制引入的
collider 问题；已显式处理平衡抽样造成的 base-rate 限制、阶段一成功条件化、断网
重跑的 regression-to-the-mean/选择性报告风险、固定三比较的 look-elsewhere 风险
及预注册后的分析自由度。v3-B 支持所选候选内的受控粒度效应描述，但不能无条件
因果外推到其他模型、Prompt 或数据集；reverse causality 不适用于先施加 Prompt
条件、后观察模型输出的设计。

### 9.1 是否继续扩展至完整 378 题

**当前建议：先完成原计划的 LiveCodeBench 60 题，再按预算决定 MBPP+ 全量扩展。**
这是针对本项目证据缺口的优先级判断，不是说 120 题能够替代全量成绩。LiveCodeBench
提供竞赛来源、带发布时间的题目，可补充不同任务与时间窗口的证据；时间标注本身
不保证对当前 Hy3 无污染，仍须核对所选窗口和已知训练截止信息。

完整 378 题的价值是消除“只测了哪个子集”的覆盖问题，取得该固定版本的全量成绩；
若论文、答辩或对比表需要写“MBPP+ 全量成绩”，则必须补齐，且还需保证比较协议一致。
目前 95/120 的区间跨度约 14.42 个百分点，扩大题目覆盖有助于减少子集抽样带来的
不确定性，但不能预先推断剩余题的通过率，也不能替代重复生成或过程层专项评测。

若实施扩展，应在生成前冻结原 120 题的补集 **258 题**、模型及 Prompt 配置和执行
条件。保留原 120 题的候选与全部判定（包括 25 个未通过），只为补集生成和执行；
合并时验证无重叠、无缺失、唯一题号恰好覆盖固定 378 题，并记录跨批次来源。若配置
或数据身份不能保持兼容，应另立实验，不能把不同条件混成同一项全量成绩。
